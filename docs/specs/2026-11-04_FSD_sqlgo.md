## 1. Background and Purpose

`sqlgo` is a SQL query builder for Go (module `gitlab.com/threetopia/sqlgo/v2`, package `sqlgo`). Callers assemble clauses with chainable methods, then call `BuildSQL()` to get a SQL string and `GetSQLGoParameter()` to get the bound values. The library targets PostgreSQL and never opens a database connection or executes a statement.

The library removes manual placeholder bookkeeping. Callers write clause calls instead of concatenating `$1`, `$2`, and values by hand, and the library keeps the SQL string and the argument slice in sync.

## 2. Goals and Success Criteria

- The same builder calls produce the same SQL string every time.
- Dynamic values are sent as bound parameters, never interpolated into the SQL text.
- The prepend/chain style and the `Set*` style produce identical SQL.
- Clause composition does not depend on the order the caller invokes clause methods.
- PostgreSQL search, trigram similarity, and vector features are available through dedicated constructors.

## 3. Scope and Exclusions

### 3.1 In Scope

- SELECT projection, FROM, JOIN, WHERE, GROUP BY, ORDER BY, OFFSET, and LIMIT.
- INSERT, UPDATE, DELETE, and standalone VALUES rows.
- Schema prefixing.
- Parameter registration, placeholder generation, and value deduplication.
- PostgreSQL full-text search with `tsvector` and `tsquery`.
- PostgreSQL trigram similarity with `pg_trgm`.
- PostgreSQL vector distance with `pgvector`.

### 3.2 Out of Scope

- A MySQL-specific builder. The `MySQLDialect` constant exists, but no builder branch uses it.
- Connection management, pooling, transactions, and query execution.
- Schema migrations, data backfill, and ORM mapping.
- Identifier validation or quoting beyond the schema prefix.
- Error reporting through Go error values.

## 4. Actors

| Actor | Responsibility |
|---|---|
| Application developer | Builds the SQL string and argument list, then passes both to `database/sql`. |
| Application service | Uses the library inside a repository or data access layer. |

## 5. Functional Requirements

| ID | Requirement | Acceptance criteria |
|---|---|---|
| `FR-001` | SELECT projection with optional aliases. | `SELECT col AS alias, col2` is emitted; an empty alias omits `AS`; multiple values are comma separated. |
| `FR-002` | FROM source with alias and optional column list. | `FROM table AS alias` is emitted; when columns are provided, `FROM table alias(col1, col2)` is emitted instead; a subquery source is wrapped in parentheses and aliased. |
| `FR-003` | JOIN with conditions. | Each join emits `<TYPE> JOIN [schema.]table AS alias ON <condition>` with the join type uppercased; multiple joins are space separated; a subquery join wraps the subquery in parentheses and appends its condition block as produced by the join clause. |
| `FR-004` | WHERE with connectors, comparison operators, and special operators. | Conditions are joined by the uppercase connector (`AND`, `OR`); the first condition has no connector; special operators include `ANY`, `ILIKE ANY`, `LIKE ANY`, `IN`, `NOT IN`, `LIKE`, `NOT LIKE`, `ILIKE`, and `NOT ILIKE`. |
| `FR-005` | WHERE `BETWEEN` and grouped conditions. | `BETWEEN` renders `(col BETWEEN $a AND $b)`; a group renders `(inner conditions)` and keeps the connector of each inner condition. |
| `FR-006` | Parameter binding and placeholder generation. | Every dynamic value is registered and rendered as `$N`; placeholders start at `$1`; identical value and type pairs share a placeholder; `GetSQLParameter()` returns values in first-appearance order. |
| `FR-007` | Schema prefix. | `schema.` is prepended to tables in INSERT, UPDATE, DELETE, FROM, and JOIN; the first schema value wins; SELECT, WHERE, and ORDER BY receive no prefix. |
| `FR-008` | GROUP BY. | `GROUP BY col1, col2` is emitted from one or more values. |
| `FR-009` | ORDER BY. | `ORDER BY col ASC, col2 DESC` is emitted; an empty direction omits the direction; embedding ordering emits `col operator $N`. |
| `FR-010` | OFFSET and LIMIT. | `OFFSET n` is emitted when offset is zero or greater and limit is greater than zero; `LIMIT n` is emitted when limit is greater than zero; the page helper derives offset as `(page - 1) * limit` for page values greater than zero. |
| `FR-011` | INSERT with one or more value rows. | `INSERT INTO [schema.]table (cols) VALUES (...), (...)` is emitted; `SetSQLInsertToTsVector` renders `to_tsvector('lang', $N)` in a value position. |
| `FR-012` | UPDATE. | `UPDATE [schema.]table SET col=$N, ...` is emitted; `SetSQLUpdateToTsVector` renders `col=to_tsvector('lang', $N)`. |
| `FR-013` | DELETE. | `DELETE FROM [schema.]table` is emitted; facade `SQLDelete` forwards its WHERE values to the WHERE module. |
| `FR-014` | Standalone VALUES rows. | `VALUES (...), (...)` is emitted from one or more value slices. |
| `FR-015` | DISTINCT ON. | `DISTINCT ON (col) col` is emitted as a SELECT item. |
| `FR-016` | Full-text search. | `ts_rank(col, to_tsquery('lang', $N))` is emitted for rank projection; `col @@ to_tsquery('lang', $N)` is emitted for filtering; `to_tsvector('lang', $N)` is emitted for insert and update values. |
| `FR-017` | Trigram similarity. | Projection emits `similarity(col, $N)`; filtering emits `similarity(col, $N) operator $M` with the threshold as a separate parameter. |
| `FR-018` | Vector embedding. | Projection emits `(col operator $N)` or `prefix(col operator $N)`; array projection emits `ARRAY[$N,$M,...]`; ordering emits `col operator $N`. |
| `FR-019` | Equivalent usage styles and fixed composition. | Prepend/chain methods and `Set*` methods produce identical SQL; `BuildSQL()` composes clauses in the fixed order defined in section 7. |

## 6. Main Flow

1. The caller creates a builder with `NewSQLGo()`.
2. The caller adds a schema and one or more clauses.
3. The caller calls `BuildSQL()`. The facade runs each clause module in the fixed composition order.
4. Each clause registers its dynamic values in the shared parameter registry and appends SQL fragments.
5. The caller reads the argument slice with `GetSQLGoParameter().GetSQLParameter()`.
6. The caller passes the SQL string and argument slice to `database/sql` with the `lib/pq` driver.

## 7. Business Rules and Validation

- Clause composition order is fixed: insert, update, delete, select, from, join, where, values, group by, order, offset/limit. The order of builder calls does not change it.
- A clause that has no values returns an empty string. `combineSQL` skips empty clauses and inserts a single space between non-empty clauses.
- The schema prefix is first-write-wins. `SQLSchema` stores a value only when the stored schema is empty.
- Identical values of the same Go type share one placeholder. Values of different types do not share a placeholder even when their printed forms match.
- `IN` and `NOT IN` enumerate slice elements as separate placeholders, remove duplicates, and keep first-appearance order. Other slice operators pass the slice through `pq.Array` and emit one placeholder.
- `SetSQLPage` computes the offset from the current limit. Call `SetSQLLimit` or `SQLOffsetLimit` before `SetSQLPage`.
- `SetSQLJoinWhere` writes a literal condition value. It is not parameterized.
- The library does not return errors. Callers are responsible for valid identifiers, supported operators, and supported value types.

## 8. Empty, Error, and Edge States

- An empty builder produces an empty SQL string and an empty parameter list.
- Passing `nil` as a value is ignored by the registry, yet the clause still asks for its placeholder sign. Avoid `nil` values because the rendered sign is not usable in a query.
- Looking up a value that was never registered returns `$-1`.
- Invalid identifiers are emitted as written. The library does not quote or escape them.
- A builder holds mutable state and is not safe for concurrent use. Treat `BuildSQL()` as the terminal call for that builder.
- Identical values are deduplicated. The current tests for `TestToTsQuery` and `TestToTsQueryPrepend` expect `$2` for a repeated value, while the registry returns `$1`. Section 8 of the DRD records this open question.

## 9. Acceptance Criteria

- `BuildSQL()` output matches the expected strings in `sqlgo_test.go` for select, insert, update, delete, where group, between, full-text, similarity, and embedding cases.
- The prepend/chain and `Set*` variants of the same query produce identical SQL and parameter slices.
- `GetSQLParameter()` returns values in the order the placeholders first appear in the SQL.
- Clause order is stable when builder calls are reordered.
- PostgreSQL feature constructors emit the documented SQL shapes.
- No dynamic value appears directly in the SQL string except literals supplied through non-parameter constructors or schema and identifier inputs.
